# Сохранение

> Красным отмечены байты, отличающиеся от файла на диске. Сохранение записывает их в файл — или, в некоторых браузерах, в скачанную копию — и красный цвет снимается.

**Что написано на кнопке, то и произойдёт.** Там, где программа может записать в открытый файл, она говорит **Сохранить**; где не может — **Скачать**, и пустой экран сообщает, что делает этот браузер, ещё до того, как вы что-нибудь открыли.

- **Сохранить** (⌘S) записывает документ панели обратно в файл, из которого он взят. Так умеют браузеры на Chromium.
- **Скачать** (⌘S) отдаёт отредактированный дамп в загрузки браузера. Firefox и Safari не умеют писать в файл, открытый страницей, поэтому сохранение там значит именно это: исходный файл не тронут, а отредактированная копия окажется там, куда идут ваши загрузки.
- **Сохранить как… / Скачать как…** записывает в новое место. После «Сохранить как…» панель переходит на новый файл; после «Скачать как…» — нет: скачанная копия странице больше не видна.
- **Файл ▸ Вернуться к сохранённому** выбрасывает правки и перечитывает файл. Для панели, чьи байты пришли из другого места — части, объединения — это **Вернуться к исходному**.
- **Записать в исходный файл** — третий адресат: для [[topic:fragments|панели фрагмента]] он записывает часть обратно в образ, из которого она взята, а не в файл.

! Файл, брошенный перетаскиванием, и файл, открытый в браузере без File System Access API, будут **скачаны** даже там, где программа умеет писать на месте — записать обратно нечем. Откройте его через **Файл ▸ Открыть…**, если хотите «Сохранить», а не «Скачать».

## Если файл не сохранён

Изменённые байты показаны **красным**, пока не сохранены, а в заголовке панели указано, что документ изменён. Сохранение снимает оба признака.

## Когда файл меняется под вами

Браузер не умеет следить за файлом, поэтому программа не замечает, что открытый на диске файл изменился — например, ваш программатор перечитал чип в тот же путь. Панель держит байты, прочитанные при открытии, и сама новое содержимое не подхватит. Единственная проверка — при сохранении, и она узкая: файл, ставший короче, отклоняется, иначе недостающие байты записались бы нулями, а переписывание в тот же размер — именно то, что даёт перечитывание, — не замечается, и сохранение зальёт новое содержимое старым. Перечитали чип — откройте файл заново перед сохранением, чтобы в панели было то, что действительно лежит на диске.

## Документы без файла

Часть документов не имеет ни имени, ни пути по своему устройству, поэтому ⌘S спрашивает, куда их записать:

- **Файл ▸ Новый файл**.
- Результат [[topic:join-duplicate|объединения]]: соединение двух дампов даёт *новый* образ, который ⌘S не должен записать поверх одной из половин.
- Результат **Дублировать**.
- Часть, вытащенная из образа.

! **Сохранить как…** записывает исправленный образ в новый файл и оставляет исходный без изменений. Средствами программы восстановить исходный дамп после его перезаписи невозможно.
