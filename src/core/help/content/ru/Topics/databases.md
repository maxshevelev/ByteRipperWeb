# Онлайновые каталоги

> Три публичных каталога, дающие имена идентификаторам, найденным в дампе. Без доступа к этим каталогам программа полностью функциональна, но не показывает расширенную информацию.

Часть того, что показывают инструментальные модули, в файле не содержится: это имя, данное сообществом идентификатору, который в файле есть. За такими именами ByteRipper обращается по HTTPS на GitHub, в три публичных каталога, и хранит полученное сутки:

- **Имена GUID UEFI** — из проекта UEFITool. Именно благодаря им [[topic:tool-uefi|инструмент UEFI]] показывает вместо голого [[term:guid|GUID]] «AmiBoardInfo» или «DxeCore».
- **Микрокод процессоров** — из коллекции CPUMicrocodes. По ней именуются обновления микрокода, которые перечисляет [[topic:tool-fit|инструмент FIT]]: сигнатура процессора, ревизия и дата. Из неё же берётся список для команды **Добавить микрокод…**.
- **База прошивок ME** — из проекта ME Analyzer. Благодаря ей [[topic:tool-me|инструмент ME]] может сказать, какому известному релизу соответствует образ.

## Где измерение, а где имя

Инструменты последовательно разделяют эти две вещи:

- **Байты принадлежат файлу.** Адрес, размер, поле версии, контрольная сумма прочитаны из самого образа.
- **Имя принадлежит каталогу.** Это опознание, сделанное сообществом: его может не быть, и оно может быть неверным.

Поэтому строка «AmiBoardInfo · 0x7A0000 · 0x12C0» означает, что в файле по этому адресу действительно есть модуль такого размера, а каталог относит этот GUID к числу тех, которые принято обозначать как AmiBoardInfo.

## Насколько свежа копия

Каталог лежит в собственном кэше браузера, поэтому у мастерской без сети есть вчерашние списки, а не пустота. Что лежит — показывается с датой, когда было получено, потому что вчерашние данные нельзя принимать за сегодняшние:

- Моложе суток — используется вообще без обращения к сети.
- Старше — используется **сразу**, а проверка идёт следом: мастерская не ждёт ради имени.
- Проверка, которая не удалась, оставляет то, что лежит, и говорит, насколько оно старое.

## Без сети

Ни одна функция программы не требует сети. Без подключения или при заблокированном запросе инструменты показывают идентификаторы вместо имён и ничего больше об этом не сообщают: ни диалогов, ни повторных попыток. Всё, что прочитано из байтов, при этом не меняется.

Обращения идут по постоянным адресам этих каталогов, и запрос не содержит ничего из открытого файла: программа загружает каталог целиком и сопоставляет его с дампом уже у себя.

Поэтому наружу не уходят ни байты образа, ни найденные в нём идентификаторы. Дамп машину не покидает.

! Очистка данных сайта стирает и сохранённые каталоги вместе с закладками и настройками. Следующий разбор загрузит их заново, если сеть есть, и обойдётся без них, если её нет.
