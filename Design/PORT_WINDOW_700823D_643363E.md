baseline `643363e`, as work units. Each unit is a separate commit that ends

### U1. The chip catalogue

Commits `6e452be`, `71a3b42`, `7a6e08b`.

Upstream rebuilt `JedecIDs.swift` into a table of `Chip{name, sizeKB, source}`
fed by three sources in precedence order — UEFITool, the Linux kernel's
SPI-NOR tables, flashrom — where a size is the first any source lists, also
for an entry named by UEFITool, and each entry keeps the source its name came
from. A weekly workflow regenerates it and opens a pull request only when it
changed.

Web target: `src/firmware/uefi/jedecIds.ts`, currently names only from the
UEFITool era. The web table stays a derivative of upstream's own generated
file, not a second scraper of the three sources: `Skills/update-jedec-ids/`
converts the upstream `JedecIDs.swift` into the TS table, and the web's
`refresh-jedec-ids.yml` fetches that file and opens a pull request when the
table changed.

Done when: `JedecChip`, `jedecChip` and `jedecCount` are anchored over
`JedecIDs.Chip`, `JedecIDs.Source`, `JedecIDs.chip` and `JedecIDs.count`; the
catalogue tests hold — 185 UEFITool-named, over fifty Linux, over a hundred
flashrom, 429 total, with the source and the size of each entry; `GAPS.md`
moves the three commits into brought across.

### U2. The VSCC table

Commits `4773ab0`, `451709c`, `9b3c629`, `bab0faa`, `4ddb57c`.

`FlashVendors` (a direct port of the twenty JEP106 first-byte codes) names the
maker of a chip the catalogue does not list, from the id's first byte, and a
code nobody knows names nothing. `DescriptorChip` gains `vendor`, `sizeKB` and
`source`. The table at `uefiNodeDetail.ts` grows a third Size column and a
fourth Source column — the project names printed verbatim — and an unlisted
chip reads "Unknown (Vendor)". The size is red where the dump does not fit
into the chip: one declared chip is measured against the image's size, several
against the smallest declared.

Done when: `DescriptorDetailTests`' four cases and the `DescriptorInfoTests`
cases hold in `uefiNodeDetail.test.ts` and `descriptorInfo.test.ts`; the new
strings are in the catalogues word for word.

### U4. Apple: BIOS ID and ROM information

Commit `48eabb4`.

Two small pure parsers: `BIOSIdentifier` (the `$IBIOSI$` signature plus
UTF-16; the five-part Intel layout — board, OEM, major, minor, `yymmddHHMM` —
read into a build date, and a body with no layout kept as text) and
`AppleROMInformation` (a text block titled "Apple ROM Version", found by its
heading line in a raw section `0x19` and in padding, a search limit of
`0x10000`, keys that repeat kept as a list of entries). Two new GUIDs in the
catalogue. The detail panel gains two tables: BIOS ID's Field/Value, and the
Apple ROM information's entries, both gated on the body fitting the limit.

Done when: the `FirmwareTextBlockTests` cases and
`testABIOSIDSectionIsATableOfItsParts` and
`testTheROMInformationInPaddingIsATable` hold; the nine shared strings are in
the catalogues word for word.

### U5. Apple: overrides and the bzip2 tab

Commits `7efdf0a`, `7c16387`.

The `overrides` system-flags variable is a bzip2 stream of a text rule table —
three tab-separated fields (the action, the device it applies to, `()` for
all, the detail) — read with a limit of `1 << 22`, a line that does not fit
kept whole. It opens as a part linked to the variable's bytes, read-only,
because nothing here recompresses.

The one real decision of the window: **the bzip2 decoder.** Upstream wraps
macOS's system `libbz2` in a system-library target; the web carries a pure-TS
decoder in `src/firmware/compression`, a port in the manner of the lzma and
tiano decoders, with upstream's contract — a limit or a reason (truncated,
too large, corrupt) — and `@upstream-differs`, because upstream asks the
system and the web carries the decoder itself. No dependency: the rule against
one without a written reason stands, and the precedent of C ports to TS is
already here.

The presenter gains `isBZip2Variable` (a system-flags entry named `overrides`)
and `unpackedTabName` (named as a decompressed body is), and "Open
Decompressed Variable" sits beside the existing "Open Decompressed Body/Bytes"
— the web already opens a decompressed body as a linked part, so the tab reuses
that mechanism.

Done when: the `BZip2Tests` (a stream to its text, a cut stream truncated,
noise corrupt, the limit kept) and the `AppleOverridesTests` cases hold;
`tool-uefi` carries the line; the new strings are in the catalogues.

### U6. Pictures: a frame, a background under click

Commit `f75883d`.

Upstream's `PicturePreviewView`: a hairline frame, because a logo is often
white or transparent and the frame is what says where the picture is; a click
cycles the background — panel, checkerboard, contrast — starting on the
checkerboard when the picture has alpha and on the panel when it does not;
the choice is not remembered.

Web target: `PicturePreview` in `src/ui/toolPanel/ToolDetail.tsx` — the frame
in CSS, the cycle in state, alpha found by decoding rather than by the mime.

**Quick Look on Space is not ported.** It is macOS's system viewer and has no
web equivalent; the decision is the owner's, 2026-10-04. The entry is
`unported` in the module map with that reason, and the Quick-Look test stays a
`later` line in the gap list.

Done when: `testAClickChangesThePicturesBackground` and
`testATransparentPictureStartsOnTheCheckerboard` hold in the web's level; the
help line in `tool-uefi` reads what the web edition actually does.

### U7. Result marks, one tint helper, the refusal rewording

Commits `6cb0ec9`, `bac7fee`, `b1c15b9`, `0ab038d`, `c7de9a4`, `457595e`.

A result that lands on an alert carries its outcome as a mark: a green
`checkmark.circle` for a success, a red filled octagon for a problem — filled,
with the mark as a hole in the fill rather than a second colour, readable on
the dark theme. `457595e` gathers every symbol the app tints for a control it
cannot hand it to into one helper, mask plus fill, because a palette of one
colour paints the mark over the hole.

`6cb0ec9` also rewords the `UEFIRebuild` refusals: they lose their "(§… of
UPDATE_IN_PARENT.md)" references. The web's refusals and their test assertions
move together, and the strings in the catalogues with them.

The web's idiom is inline SVG shaped after the named SF Symbols, so the marks
are drawn the same way and the "one helper" is one function that returns a
symbol filled with a colour, `@upstream-differs` for the drawing.

Done when: the refusal strings and their tests hold, `LinkedPartTests`'
outcome case holds in the web's level, and the changed strings are in the
catalogues.

### U8. Microcode in modal sheets

Commit `c4d7136`.

`ToolHost` gains `beginBlockingWork` and `report`. The FIT tool's add, replace
and remove stop writing into the panel's bottom line and run in a sheet: a
busy sheet with phases and a cancel while the work runs, and a result sheet —
what was done, or why it was not — when it ends. A read-only file refuses
before the work begins.

The web has no AppKit sheets: the adaptation is a modal overlay over the
window, with the web's existing cancellable workers for the phases.

Done when: the reworked `FITToolFlowTests` cases hold in the web's level and
`SeamTests`' six new ones; the eleven new strings are in the catalogues.

### U9. The pane header: Modified and Update in Parent

Commits `ddfc9db`, `1662b81`.

The mechanism the button stands on is already the web's — Update in Parent is
a pane-menu command. What is unported is the offer in the header and its
final form: one bordered button, "Modified" with the download glyph, right
after the parent's name, small, holding its words while it yields to a long
parent name, taking no place while it is not shown. It is offered while the
part is modified and the document it was opened from is still open, re-checked
on every status refresh, because the parent changing is also how a pane learns
its changes went back. The result says where the undo takes the part back.

Done when: `LinkedPartTests`' cases hold in the web's level; `fragments` reads
what the web edition does, in all three languages; the new strings are in the
catalogues.
