# ByteRipperWeb — gaps with ByteRipper

What is still left to port from the macOS app, and what the web edition will
not support, as tables to prioritise from.

The module map (`Skills/port-from-byteripper/reference/module-map.json`) is the
symbol-level truth: every upstream declaration left out carries a `later —` or
`n/a —` reason there. This file groups those reasons into things a person can
decide about. `Design/ANALYSIS.md` remains the record of *why* a feature is
dropped or adapted; this file is the list.

## Keeping it current

This file is updated in the same change that:

- **closes a gap** — the row moves to [Closed](#3-closed) with the date;
- **leaves something out** — a new `later —` entry in the module map belongs to
  a row here (an existing one, or a new ID);
- **drops or adapts a feature** — a row in [section 2](#2-not-supported-in-the-web-edition),
  and the verdict in `Design/ANALYSIS.md`.

To check the tables against the map:

```bash
python3 Skills/port-from-byteripper/scripts/unported_summary.py --later --no-tests
python3 Skills/port-from-byteripper/scripts/unported_summary.py --na --no-tests
```

The map, and so the summary, covers upstream's non-private declarations only:
the anchor check does not ask for a `private` helper to be anchored, because a
port folds most of them into the code it does anchor. Behaviour that lives only
in a private function can therefore be missed without the check saying so — the
hex field formatting (`FindBarView.normalizeHexText`) was. Rows found that way
(G32, G33 and part of G18, all now closed) name the private functions in
*Upstream* and have no map entries. The audit that finds them:

```bash
python3 Skills/port-from-byteripper/scripts/private_audit.py
```

Columns:

- **ID** — stable, never reused, so a conversation can say "G4".
- **Size** — upstream declarations still unported for the gap, from the summary.
  A measure of weight, not of effort: one C decoder counts as a handful.
- **Priority** — P1 first. A proposal until the owner changes it.
- **Status** — `open`, `in progress`, or `decision` when it waits on a choice
  nobody has made yet (named in *Depends on*).

| Pane dragging, ported from the header — everything except the New Tab strip the owner excluded. A pane is picked up by its header and carried as a pill: over another pane's bands it swaps, joins at either end, or duplicates with Option held; over its own middle band it is refused; dropped outside every target nothing happens; in single-file mode the workspace splits for the drag and its free half takes the pane as a copy. | G38 — The drag dead zone, ported. A click that lands between a byte's nibbles — from the middle of the high-nibble character to the middle of the low-nibble one (§3.3) — is a caret position, and the drag boundary sits on the byte's centre, so a 1 px jitter there used to select the byte by accident. `HexView.dragHasLeftDeadZone(from:to:)` is `dragHasLeftDeadZone(layout, origin, point, rowCount)` in `src/ui/pane/hexPointer.ts`, beside the other pointer rules G19 left there: the press is hit-tested, and only a press inside the hex column's dead zone — `HexLayout.highNibbleMidX` to `lowNibbleMidX` on the pressed row, both edges inclusive, as upstream's comparisons are — holds the selection back until the pointer leaves it. The zone spans the pressed row, so vertical movement engages it too, and a press anywhere else — a byte's outer quarters, the offset or text columns, anywhere the layout cannot place in a row — is a clear position and engages at once. A **Shift**-press skips the wait the same way, which is what makes the press mean two things: `dragRef` is upstream's `dragEngaged` and now starts as the Shift key has it, and a new `pressRef` holds upstream's `mouseDownLocation` in content coordinates while the button is down, cleared on the release — so a pane the pointer merely hovers over has no press to answer for. Until it engages, a move does nothing at all: the zone is checked before `dragTo`, so neither a scroll nor the autoscroll timer starts while the gesture is still a click. The web had no zone at all — it extended on every pointer move, so a hand resting on a nibble boundary selected a byte. `hexPointer.test.ts` gains five tests for the rule: the jitter inside it, each inclusive edge, leaving it left and right, the row span, and the presses that are clear from the start — two of them porting `MouseSelectionTests.testJitterInDeadZoneDoesNotSelect` and `.testDragOutOfDeadZoneSelectsFromClick`, so those two map entries and the one for `HexLayoutTests.testDeadZoneMidlines` (already covered by `hexLayout.test.ts`, which now carries its anchor) are gone; `testDragLeftFromNibbleGapSelectsPreviousByte`, whose other half is `dragEndOffset`, keeps its `later` entry without the parenthetical the closed gap no longer needs | 2026-09-16 |

| G19 — The pointer's place inside a byte, and the frame a menu draws around what it is about. **A click reads the nibble off the pointer's x within the byte** rather than always landing on the byte's left boundary: `HexView.hexClickPlacement(atX:column:layout:)` is `hexClickPlacement(layout, x, column, insertMode)` in `src/ui/pane/hexPointer.ts` with upstream's two thresholds — in overwrite mode the byte's own centre, so the high digit's second half is still its zone; in insert mode the middle of the high-nibble character, since a half-typed byte is about to move the caret there anyway — and the gap before a byte goes to the previous byte's low nibble when the click is in its nearer half, `column > 0` only, so a click before column 0 has nowhere else to land.
